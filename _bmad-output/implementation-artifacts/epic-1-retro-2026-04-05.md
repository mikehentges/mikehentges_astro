## Successes

1. **Complete foundation delivered in 3 days** — from brownfield Astro 4.5 codebase to fully scaffolded Astro 6 project with design system, navigation, footer, accessibility, and deployment config.

2. **Critical thinking during implementation** — Dev agent caught that `@astrojs/cloudflare` adapter is unnecessary for static sites, Tailwind v4 has no `tailwind.config.ts`, and Satoshi is on Fontshare not Fontsource. Prevented real downstream issues.

3. **Code review process caught real issues** — Story 1.1 review found 6 actionable items: stale CLAUDE.md referencing SCSS, missing `prettier-plugin-astro`, malformed `pnpm-workspace.yaml`, missing `.vscode/` in gitignore, missing sitemap directive in robots.txt. These were things that would have caused problems later.

4. **Spec format evolved and improved within the epic** — Story 1.1 used a task-list format and had the most review findings. Stories 1.2-1.6 adopted the frozen-intent format with Boundaries & Constraints, I/O matrices, and explicit Always/Ask First/Never rules. Review findings dropped significantly.

5. **Accessibility baked in from day one** — Skip link, focus-visible styles, landmark structure, aria-current, responsive typography, and progressive enhancement (noscript fallback) were all in specs and built as first-class features, not afterthoughts.

6. **Deferred work tracked cleanly** — 9 items logged in deferred-work.md with origin story, clear descriptions, and forward pointers. No scope creep during implementation.

## Challenges

1. **Architecture doc had stale assumptions** — 3 of 6 stories (1.1, 1.2, 1.4) had to correct or work around assumptions from the architecture document. The Cloudflare adapter, `tailwind.config.ts`, and font provider references were all wrong for the actual tech stack versions.

2. **Technical claims in specs not validated against current documentation** — The Fontsource vs Fontshare issue, Tailwind v4 config approach, and Cloudflare adapter situation were all discoverable by checking official docs, but validation happened during implementation rather than during spec creation.

3. **Deployment environment mismatch** — Story 1.6 was marked done but Cloudflare Pages builds were failing. Root cause: Cloudflare's default pnpm 8.7.1 couldn't read the pnpm 10.x lockfile, causing a fresh dependency resolve that pulled Vite 8 (incompatible with Astro 6's Vite 7). Caught during this retrospective.

4. **Story 1.1 spec format weaker than later stories** — The task-list format left more room for assumptions and generated more review findings than the frozen-intent format adopted for 1.2-1.6.

---

## Key Insights

1. **Shift validation left** — Verify technical assumptions against real, current documentation before specs are frozen. Architecture should validate big decisions; story specs should cite sources for implementation-specific claims. This prevents the dev agent from having to diagnose and correct spec errors mid-implementation.

2. **Pin your deployment environment** — "Works locally" isn't done until CI/CD agrees. Lockfile compatibility, package manager versions, and Node versions must match between local and deployment. This should be verified as part of any deployment story.

3. **The frozen-intent spec format works** — Stories with Boundaries & Constraints, I/O matrices, Code Maps, and explicit Never lists had fewer review findings and cleaner implementations. Standardize on this format.

4. **Deferred work tracking prevents scope creep but needs triage** — The pattern of logging items with origin and forward pointers works well, but items need periodic review to avoid silent accumulation and ensure cross-epic impacts are caught.

## Deployment Fix Applied During Retrospective

During the readiness check, Mike reported Cloudflare Pages builds were failing. Analysis of the build log revealed:

- **Symptom:** `astro check` fails with TypeScript error — `Plugin<any>[]` (Vite 8) not assignable to `PluginOption` (Vite 7)
- **Root cause:** Cloudflare's default pnpm 8.7.1 can't read pnpm 10.x lockfile format; ignores lockfile and resolves fresh, pulling Vite 8 via `@tailwindcss/vite` which is type-incompatible with Astro 6's Vite 7
- **Fix:** Added `"packageManager": "pnpm@10.12.1"` to package.json and `[build.environment]` with `PNPM_VERSION = "10.12.1"` and `NODE_VERSION = "22"` to wrangler.toml
- **Status:** Fix applied locally, needs push + Cloudflare build verification
